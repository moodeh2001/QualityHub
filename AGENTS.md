# QualityHub Learning Rules

These rules apply to future Codex sessions in this workspace.

- Guide one step at a time.
- Wait for the project owner's explicit confirmation before progressing to the next learning step.
- Let the project owner write implementation code personally.
- Review the project owner's attempts and explain specific mistakes.
- Do not implement solutions unless implementation is explicitly requested.
- Never invent requirements, defects, evidence, metrics, or test results.
- Never claim tests passed without executing them.
- Keep progress records accurate, distinguishing reported observations from checks executed in the current session.
- Preserve existing files and protect local credentials. Never request, copy, or commit the sandbox key.

## Project context and boundaries

QualityHub tests the existing LearnQA QA Shop application; it does not build a new shop. Planned features must not be described as completed until implemented and verified.

The initial workspace preparation authorizes only scaffolding and supporting documentation. It does not authorize implementation code, manual test artifacts, integrations, package installation, environment or Docker changes, application writes, tests, performance runs, commits, pushes, or Git configuration changes. Obtain explicit direction before beginning subsequent work.

Frontend reproducibility without the temporary DevTools Service Worker bypass remains unresolved. Preserve that limitation in documentation until evidence establishes a solution.
